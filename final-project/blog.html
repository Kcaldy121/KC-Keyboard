Rhythm Transcription System

Development Blog & Project Reflection

Project Overview

This project explores the creation of a browser-based rhythm transcription and notation system using JavaScript, the Web Audio API, and VexFlow. The application allows users to input rhythms in real time through keyboard interaction and dynamically converts those rhythms into symbolic musical notation.

The idea for the project came from my own experiences with music arranging and transcription. I often found myself struggling with quickly identifying note lengths and translating rhythmic ideas into sheet music. Existing rhythm trainer applications inspired the interaction model, but I wanted to extend the concept by generating actual notation directly in the browser into something that resembles sheet music more.

The project focuses on bridging intuitive musical performance gestures with formal notation systems. In addition to rendering notation visually, the system also includes tempo controls, rhythmic quantization, metronome playback, and automatic rhythmic grouping.

Although the current implementation focuses primarily on rhythmic transcription, one of the main future directions for the project is integrating microphone-based pitch detection through FFT analysis. The Web Audio API’s `AnalyserNode` provides access to frequency-domain data in real time, which can be used to estimate the fundamental frequency of incoming audio signals. My goal is to allow users to sing or play notes into a microphone and automatically convert those detected frequencies into symbolic pitch information that can be rendered alongside rhythm notation. The planned pitch detection pipeline would involve capturing live audio input from the microphone, passing the signal through an `AnalyserNode`, and applying FFT analysis to identify dominant frequency peaks. These frequencies could then be mapped to the nearest pitch classes and octave ranges using equal temperament calculations. This would expand the project from a rhythm-only transcription tool into a more complete browser-based music transcription environment capable of handling both temporal and melodic information. The project also incorporates a browser-based metronome built using the Web Audio API. The metronome uses an `OscillatorNode` to generate short synthesized click sounds and a `GainNode` to shape the amplitude envelope of each click. Rather than using prerecorded audio samples, the metronome synthesizes its clicks dynamically in real time through oscillator frequency control and gain ramping. The timing interval for each click is calculated directly from the selected BPM value, allowing the metronome to synchronize with the rhythm quantization system used elsewhere in the application. Using WebAudio for the metronome also introduced practical timing considerations. Browser event scheduling and audio timing are not perfectly deterministic, especially when relying on JavaScript timing functions alone. While the current implementation uses interval-based scheduling for simplicity, future versions could move toward more accurate audio scheduling techniques using `audioContext.currentTime` to achieve tighter synchronization and lower rhythmic drift.

Development Process

The project began as a simple rhythm input tool that recorded keyboard taps and measured the spacing between them. Initially, rhythms were displayed only as text labels such as quarter notes or eighth notes.

From there, the system evolved into a much more complicated notation-rendering project. Once notation rendering was introduced through VexFlow, additional challenges emerged involving rhythmic spacing, beaming, measure alignment, and note grouping.

One major issue involved repeated key events while holding down the spacebar. The browser repeatedly fired keydown events, which unintentionally generated streams of short notes. This was eventually solved by separating note-on and note-off behavior using both keydown and keyup listeners.

Another challenge was handling rhythmic beaming. At first, VexFlow generated overlapping beams and note flags, creating cluttered notation. This required restructuring the rendering order so beam groups were attached before drawing the notes themselves.

What I Learned

This project taught me how complex symbolic music notation systems actually are. At first, I assumed notation rendering would mostly involve drawing note symbols on a staff, but I quickly realized that accurate engraving depends on timing structures, measure logic, rhythmic grouping, and spacing rules.

I also gained experience with browser-based audio systems through the Web Audio API. Building the metronome helped me better understand oscillators, gain envelopes, and real-time audio scheduling.

Working on this project also strengthened my understanding of JavaScript event systems, especially timing-sensitive interactions such as keydown and keyup handling.

Future Work

I definitely want to continue expanding this project beyond its current functionality. One of the biggest remaining goals is implementing true measure-aware notation formatting. Currently, the notation system visually displays barlines, but the rhythmic logic itself is not yet fully organized by measure boundaries.

Future versions would split notes dynamically across measures, support tied notes over barlines, and automatically organize notation spacing according to beat structure.

I also want to incorporate microphone-based pitch detection using FFT analysis through the Web Audio API’s AnalyserNode. This would allow users to sing or play notes directly into the browser and generate melodic notation alongside rhythmic transcription.

Additional future goals include MIDI export, playback synthesis, polyphonic transcription, automatic accompaniment, and support for more advanced rhythmic structures such as tuplets and swing rhythms.
